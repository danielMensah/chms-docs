title: "Importing members"
description: "Import members into a branch from a CSV file: choose the file, map columns, review the data, and check import history in Bethel ChMS."
---

Use **Import Members** to add many members at once from a spreadsheet, instead of creating each record by hand. Save your spreadsheet as a **CSV file** (comma-separated values, a plain format that Excel, Google Sheets and Numbers can all export) and Bethel ChMS walks you through four steps: **Choose file**, **Map columns**, **Review** and **Done**.

Every import goes into one branch. No members are added until you confirm the import at the end of the **Review** step.

<Info>
**Who can do this:** Org Owner, Org Admin, Branch Admin. Editors, Treasurers and Care Managers cannot import members.
</Info>

## Before you import

Prepare a `.csv` file with a header row (the column names) and one row per member. The import accepts:

- Up to 700 rows per file
- Files up to 5MB
- The built-in member fields listed below
- Your organisation's active member custom fields

**First Name** and **Last Name** are required. Every other field is optional.

| Field | What to put in it |
| --- | --- |
| **First Name** | Required. |
| **Last Name** | Required. |
| **Email** | Used to spot duplicates. |
| **Mobile Number** | Used to spot duplicates. |
| **Date of Birth** | A date such as `15/03/1990`, `1990-03-15`, `15 March 1990` or `March 15, 1990`. Bethel ChMS works out the member's age group from it. |
| **Age Group** | Only used when **Date of Birth** is blank. Use the name or the age range of one of your [age groups](/guides/age-groups), for example `Children`, `13-19` or `35+`. |
| **Gender** | Male, female, other or prefer not to say. Short forms such as `m` and `f` also work. |
| **Nationality** | A recognised nationality, for example `British`. |
| **Address** | Free text. |
| **Post Code** | Free text. |
| **Status** | The member's lifecycle status: `newcomer`, `active` or `inactive`. `new` and `n` also mean Newcomer, `member`, `regular` and `a` mean Active, and `lapsed` and `i` mean Inactive. |

If you leave **Status** blank, or do not include it, the member is imported as **Newcomer**. See [Managing members](/guides/managing-members) for what each status means.

Dates in a custom field that holds a date can be written in the same ways as **Date of Birth**.

<Tip>
Start from the template so your column names match what Bethel ChMS expects. The template already includes a column for each of your member custom fields.
</Tip>

## Open Import Members

In the sidebar, open **Organisation** and click **Import**. The page is titled **Import Members**. On a phone or a tablet held upright, tap **More**, then **Import**.

You can also open it from the **Members** page: open the **⋯** menu and choose **Import members**.

If you are an Org Owner or Org Admin, choose the branch you want to import into with the branch selector before you start. The wizard shows **To** followed by the branch name, so you can check where the members will go. See [Find your way around](/getting-started/find-your-way-around) for where the branch selector sits on each device.

## Step 1: Choose your file

<Steps>
  <Step title="Download the template (optional)">
    In the **Start from the template** card, click **Download Template**. Fill in one row per member and save the file as CSV.
  </Step>
  <Step title="Choose the file">
    Click **Choose a CSV file** and select your file. On a computer, you can also drag the file onto the card.
  </Step>
</Steps>

Bethel ChMS checks the file straight away. If it is larger than 5MB, has more than 700 rows, or is not a valid CSV file, you see a message explaining the problem and nothing is imported. Fix the file and choose it again.

## Step 2: Map columns

In **Map Columns**, you tell Bethel ChMS which member field each column in your file belongs to. Each column from your file appears as its own card, with a few sample values from that column and a **Maps to** list.

Bethel ChMS matches common column names for you, whatever their capitalisation. For example, `surname` maps to **Last Name**, `phone` to **Mobile Number** and `dob` to **Date of Birth**. A column named exactly like one of your custom fields maps to that custom field. Columns Bethel ChMS cannot match start as **Skip This Column**.

<Accordion title="Column names Bethel ChMS recognises">
- **First Name:** first name, firstname, given name, fname, first
- **Last Name:** last name, lastname, surname, family name, lname, last
- **Email:** email, email address, e-mail
- **Mobile Number:** mobile, mobile number, phone, phone number, cell, cell phone
- **Date of Birth:** dob, date of birth, birth date, birthdate, birthday
- **Age Group:** age group, agegroup, age cohort, age band
- **Gender:** gender, sex
- **Nationality:** nationality
- **Address:** address, street address, home address
- **Post Code:** post code, postcode, zip, zip code, postal code
- **Status:** status, membership status, member status

The column names used in the template, such as `first_name`, `mobile_number` and `post_code`, are recognised too.
</Accordion>

Check each card and change any mapping that is wrong:

- Choose a field under **Built-in Fields** or **Custom Fields**.
- Choose **Skip This Column** for any column you do not want to import. Skipped columns are marked **Skipped** and are not imported.

Each field can be mapped to only one column. A field that is already in use is greyed out in the other columns' lists. To move it, set its current column to **Skip This Column** first.

The page confirms **Required fields mapped: First Name, Last Name** when both required fields are mapped. If one is missing, you see which, and you cannot continue until you map it. Chose the wrong file? Click **Replace** on the file card to start again.

When the mapping looks right, click **Continue to Validation**.

### Create a custom field during import

If your file has a column that does not match any existing field, an Org Owner or Org Admin can create a new member custom field without leaving the import.

1. Open that column's **Maps to** list and choose **Create New Custom Field** under **Actions**.
2. In **Create New Custom Field**, check the **Label**. It starts as your column name.
3. Choose a **Field Type**: **Text**, **Number**, **Date**, **Yes / No** or **Single Select**. Bethel ChMS suggests a type based on the values in the column. A **Single Select** field needs at least two **Options**.
4. Turn on **Required field** if the field should be required on member records.
5. Click **Create Field**.

The new field is added to your organisation's member custom fields, and the column is mapped to it. You can manage it later in [Organisation settings](/guides/organisation-settings).

<Note>
Branch Admins can map columns to existing custom fields, but cannot create new ones. Ask an Org Owner or Org Admin to add the field, then import again.
</Note>

## Step 3: Review your data

### Confirm date formats

If the dates in your **Date of Birth** column, or in a custom date field, could be read two ways, for example `03/04/1990`, Bethel ChMS asks you to confirm the format before you see the preview. Choose **DD/MM/YYYY** (day first, as used in the UK) or **MM/DD/YYYY** (month first, as used in the US).

### Check the validation preview

**Validation Preview** shows how each row will be imported. Bethel ChMS tidies values into a standard format, for example turning `m` into `male` or `lapsed` into `inactive`. Values it changed are highlighted in yellow so you can check them.

At the top, three summary cards show how many rows are **Ready to import**, how many are **Duplicates** (these will be skipped) and how many have **Errors** (these block the import).

Each row carries a badge:

- **OK**: the row is ready to import.
- **OK · Note**: the row will import, with a note to read. This happens when a row has both a date of birth and an age group: the age group is worked out from the date of birth instead.
- **Duplicate**: the row will be skipped.
- **Error**: a value needs fixing.

Use the chips **All rows**, **Errors**, **Duplicates** and **Notes** to show only one kind of row. The preview shows 50 rows at a time. Click **Show 50 more rows** to see the next ones. When fewer than 50 are left, the button shows how many remain.

### Fix errors

You cannot import while any row has an error. Each error is shown on its row, for example a blank first or last name, a gender or status that is not recognised, a date that does not exist, a nationality that is not on the list, an age group that matches none of your age groups, or a **Single Select** value that is not one of the field's options.

To fix errors, correct your CSV file and click **Upload fixed file**. This takes you back to **Choose file**, so you choose the corrected file and check the column mapping again. If a column was mapped to the wrong field, click **Back to Mapping** instead.

### How duplicates are found

A row counts as a duplicate when:

- It has the same email address or mobile number as an earlier row in the same file. The row says which row it duplicates.
- It has the same email address or mobile number as a member already in the branch. The row names the existing member it matches.

Duplicate rows are skipped, so existing member records are never overwritten.

<Tip>
After an import, open the **⋯** menu on the **Members** page and choose **Possible duplicates** to look for people who may have been added twice under slightly different details. See [Duplicates and merging](/guides/duplicates-and-merging).
</Tip>

## Step 4: Import and finish

<Note>
Each new member who has an email address is sent an email with their personal check-in QR code, just as when you add a member by hand. Check the email addresses in your file before you import.
</Note>

<Steps>
  <Step title="Start the import">
    At the bottom of the **Validation Preview**, click **Import** followed by the number of members, for example **Import 120 Members**. The button is available once there are no errors and at least one row is ready.
  </Step>
  <Step title="Confirm">
    Bethel ChMS tells you how many new members will be added to the branch and how many duplicate rows will be skipped. Click **Import**.
  </Step>
</Steps>

The wizard moves to **Done** while Bethel ChMS imports the members.

When the import finishes, you see **Import Complete** with the number of members imported and any duplicates skipped. Click **View Members** to see them in the member list, or **Import Another File** to start again.

If something goes wrong, you see **Import Failed**. No records are imported, so you never end up with half an import. The page shows the reason and, where available, a **Reference** you can quote to support at hello@bethelware.app. Click **Try Again** to start over.

## Age groups and imported members

You can include **Date of Birth**, **Age Group**, or both.

- When a row has a **Date of Birth**, Bethel ChMS works out the member's age group from it, using your [age groups](/guides/age-groups).
- When **Date of Birth** is blank, Bethel ChMS uses the **Age Group** column instead.
- When a row has both, the date of birth wins. The row still imports, marked **OK · Note**.

## Import History

**Who can do this:** Org Owner, Org Admin, Branch Admin

Open the **Import History** tab on the **Import Members** page to see the 50 most recent imports into the branch you have selected, including failed ones. Branch Admins see the imports into their own branch. For each import you see the **File**, the **Date**, how many members were **Imported** out of the rows in the file, how many rows were **Skipped**, the **Status** (**Completed** or **Failed**) and who it was **Imported by**.
